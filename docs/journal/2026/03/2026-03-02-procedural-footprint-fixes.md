# Fix Procedural Building Footprints (Church, Silo+Barn) + Regenerate All Test Cases

## Problem

Two procedural building families had incorrect footprints generated by `convexHull2D`, which creates convex outlines that don't follow the actual building wall angles for concave shapes.

### Church (proc-church-*)

`generateChurch` produces an L-shaped building: a rectangular nave with a square tower protruding from one end. The convex hull created a hexagonal footprint with diagonal edges at the nave-tower junction instead of right angles.

```
  Correct (L-shape)          convexHull2D (hexagon)
  ┌─────────┬──┐             ┌─────────╱──╲
  │  nave   │T │             │  nave  ╱ T  ╲
  │         │  │             │       ╱     ╱
  └─────────┴──┘             └──────╲   ╱──
                                     ╲╱
```

### Silo with barn (proc-silo_with_barn-*)

`generateSiloWithBarn` produces a rectangular barn with a cylindrical silo attached to one end. The convex hull merged both shapes with diagonal bridging edges instead of following the barn rectangle into the silo arc.

Additionally, the silo had a 2m gap from the barn wall (the `gap` parameter default). This gap created a 16.2 m² hole (3.5% of footprint area) that was architecturally unrealistic.

## Fix

### Church footprint

Replaced `convexHull2D` with an explicit 8-vertex L-shaped footprint:

```javascript
const footprint = [
  { x: -nhl, z: -nhw },  // nave SW
  { x: -nhl, z: nhw },   // nave NW
  { x: nhl, z: nhw },    // nave NE
  { x: nhl, z: tClipZ }, // junction N
  { x: tEastX, z: tClipZ },  // tower NE
  { x: tEastX, z: -tClipZ }, // tower SE
  { x: nhl, z: -tClipZ },    // junction S
  { x: nhl, z: -nhw },   // nave SE
];
```

### Silo with barn footprint

1. Removed the `gap` parameter — silo is now tangent to the barn east wall (`siloX = barn_l/2 + silo_r`).
2. Replaced `convexHull2D` with an explicit footprint: barn rectangle edges + angular arc sweep around the silo:

```javascript
const topAngle = Math.asin(Math.min(1, bridgeZ / silo_r));
const arcPts = [];
for (let i = 0; i <= arcSteps; i++) {
  const a = topAngle - (topAngle - botAngle) * i / arcSteps;
  arcPts.push({ x: siloX + silo_r * Math.cos(a), z: silo_r * Math.sin(a) });
}
// barn rectangle SW → NW → NE, bridge to arc, arc, bridge back, barn SE
```

### Other families checked

All 21 procedural types were audited. Only church and silo_with_barn needed fixes:
- 5 types already had explicit footprints (split_level, cross_plan, cathedral, cross_plan_tower, u_shaped)
- 14 types are convex shapes where convexHull2D is correct (gable, hip, flat, mansard, gambrel, shed, sawtooth, butterfly, dome, pyramid, barrel_vault, silo, t_shaped, l_shaped)

## Test case regeneration

All 189 proc-* test cases (21 types × 3 sizes × 3 noise variants) were regenerated.

### Why full regeneration was needed

Within each size group (same roof seed), the clean/standard/noisy variants had **different geometries** — different areas, different plane parameters. This happened because test cases were generated from an older version of `generateRandomized` before newer building types were added. Since `generateRandomized` eagerly computes ALL type defaults (consuming RNG state), adding types shifted the RNG positions for all subsequent types.

### Regeneration approach

A script generates geometry once per (type, size) seed, then creates 3 noise variants with different `cloudParams` (noise, outlier_rate, density) sharing identical ground truth. This ensures:
- Consistent ground truth across clean/standard/noisy for the same roof
- Correct footprints from the updated generators
- Fresh `content_hash` values matching actual data
- `validated: true` preserved on all test cases

## Impact

| Aspect | Impact |
|--------|--------|
| GT composite scores | Church and silo_with_barn footprint metrics will improve (no more overshoot from convex hull diagonals) |
| Other families | Ground truth regenerated but geometry unchanged (convex hull was already correct) |
| Pipeline cache | All proc-* cache entries invalidated (point clouds changed due to footprint-dependent ray casting) |
| Benchmark DB | Old proc-* results not directly comparable — different point clouds |

## Files changed

- `lib/real-buildings/procedural-buildings.js` — church footprint, silo_with_barn footprint + gap removal
- 189 `test-cases/proc-*.json` — regenerated with consistent GT

## Lessons

1. `convexHull2D` is only correct for convex building outlines. Any concave shape (L, T, U, composite) needs an explicit footprint.
2. The footprint affects point cloud generation (`pointInPolygon2D` in ray casting), so changing a footprint changes the entire test case — not just metrics.
3. When `generateRandomized` eagerly consumes RNG for all types, adding new types shifts seeds for all existing types. Test cases should be regenerated as a batch when the generator evolves.
